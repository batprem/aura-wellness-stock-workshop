# Skill: changelog entry

> EXAMPLE LAYOUT — NOT REAL AURA DATA. This matches the example on the Module 4 slides. It is not an official format. It describes how to do one task; project scope stays in CLAUDE.md.

## When to use
After each build of the app.

## Result
A short, dated entry at the
top of the changelog.

## Steps
1. List what changed for users
2. List what was fixed
3. Note what is not done yet
4. Add the build [number]
5. Ask the owner to review

## Tone
Plain words, no code details.
